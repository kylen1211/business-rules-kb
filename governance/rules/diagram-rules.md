| 图类型 | 使用位置 | 母版 |
|---|---|---|
| 业务流程图(3.1,链路局部图) | 业务规则页(`DATA_BUSINESS` 下 `<业务id>.md`)每条链路上方 | `sum-svg-diagram` skill 业务流程图母版 |

## 二、四种版式(证据来源与落位,画法与版式一律见 `sum-svg-diagram` skill 当场判断)

### 3.1 业务流程图

- **证据来源**:节点内容取自该链路自身的流程文字与决策表(触发点、分支结果、共享前提),取材自该业务规则页(`DATA_BUSINESS` 下 `<业务id>.md`)对应链路部分,不臆造该链路之外的节点或分支。
- **业务 id 关联**:该链路对应一张图,落盘 `DATA_IMAGES` 下 `<业务id>-<链路名>.svg`(链路名 ASCII 短横线 slug,不用中文,见五)。组装步骤先机械占位,真图产出与出图时机见独立流程 `GOVERNANCE_FLOW` 的 `diagram-draw.md`,本文件不判断"是否出图"。

### 3.2 全局业务图

- **证据来源**:项目代码本身(模块顶层 docstring、关键函数体,尤其是核心流程"会话管线装配"行锚点对应的代码——它字面上就是一份可执行的处理链顺序清单,是本项目"业务如何流转"最直接的机械证据源);业务页(草稿或已建页)如果存在,可以作为**佐证**加快理解,但不能替代代码作为唯一依据,也不能用"业务页没写"当作某条流转关系不存在的理由——所有判据都要求能在代码里独立复核。
- **图数量**:只画一张整体图,覆盖全部已知业务,存 `DATA_IMAGES` 下 `overview-flow.svg`。

### 3.3 业务全貌图

- **证据来源**:该业务规则页自身(`DATA_BUSINESS` 下 `<业务id>.md`)的"流程文字"节与"决策表"节,取材到决策表节点这一级(如 C01、C02、D01–D06);分支级最细粒度(如某节点内部逐条分支各自的判定条件)仍以该链路自己的局部图(3.1)为唯一权威来源,业务全貌图不逐分支拆卡。
- **业务 id 关联**:该业务对应一张全貌图,一页一张,存 `DATA_IMAGES` 下 `<业务id>-overview.svg`,插入位置见 `GOVERNANCE_RULES` 的 `business-rule.md` 二(页头之后、流程文字之前)。组装步骤先机械占位,真图产出与出图时机见独立流程 `GOVERNANCE_FLOW` 的 `diagram-draw.md`,本文件不判断"是否出图"。

### 3.4 全局架构图

- **证据来源**:项目实测事实——代码、配置、运行时组件的实际部署位置(是否在客户端进程内 / 核心会话服务进程内 / 进程边界之外的外部服务),不臆造未经核实的组件或交互。
- **业务 id 关联**:全局架构图不挂靠单个业务 id,一项目一张,落盘固定 `DATA_IMAGES` 下 `architecture-overview.svg`。
