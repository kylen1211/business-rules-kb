# kb 业务规则流程 · 入口分诊

> 治理入口见 `ENTRY_AGENTS`;本页是"这批改动该进哪条流程"的唯一裁决点。三条流程(初始化 `GOVERNANCE_FLOW_INIT`、更新 `GOVERNANCE_FLOW_UPDATE`、概览首建 `GOVERNANCE_FLOW` 的 `overview-init.md`)内部不做跨流程转移决定——流程内部执行到中途发现"这批改动不该按本流程方式处理",只能停止并交回本页重新分诊,不能自己断言"去走另一条流程"。

## 分诊判据

1. 业务页(`DATA_BUSINESS` 下 `<业务id>.md`)不存在 → 走 [`init/README.md`](./init/README.md)**骨架档三步**(初始化一律先做骨架档,见 `GOVERNANCE_RULES` 的 `business-rule.md` 三;只有明确需要细节档时才走五步,从 step1 开始;出图已独立成 `GOVERNANCE_FLOW` 的 `diagram-draw.md`,不占编号)。
2. 业务页已存在:
   - **本次触碰只是分支/连线/终态级改动,页仍是当前 `tier`**(不构成升档)→ 走 [`update/README.md`](./update/README.md)(更新,六步)。触发源两种,决定从哪一步进入:
     - **代码有改动**(常规情形):从 step1(规则草稿)开始,按顺序走完六步。
     - **代码未改动、纯治理性判据/规则本身扩展要求重新审视页面结构**(如 `ENTRY_AGENTS`"治理性修订的传导与重审义务"描述的判据扩展场景):没有"开发动手前的规则草稿"可言,跳过 step1,直接从 step2 开始,并在 step2 产出里注明触发源为"治理重审"。
   - **页存在且 `tier:骨架`、本次改动触碰某节点内部的分支行为**(升档判定见 `GOVERNANCE_FLOW_UPDATE` 的 `README.md`"从业务页出发的核对动作"六步第 6 步)→ **升档**,走 [`init/README.md`](./init/README.md) 的细节档五步(从 step1 重做),不走 update。
3. 全局概览页(`ENTRY_OVERVIEW`)首次生成/重建 → 走 [`overview-init.md`](./overview-init.md)(一次性)。
4. 业务页任意一次组装通过校验后的同步动作 → 走 [`overview-sync.md`](./overview-sync.md)。这不是一条独立分诊目标,是 init/update 两条流程各自 step6 内部调用的共享收尾子程序(无独立判断权),不经过本页分诊,由触发它的那条流程直接调用。
5. 需要给某张图补真图、重画、或升级画法(不区分业务页图槽位还是概览页图槽位,覆盖四类图:链路局部图/全局业务图/业务全貌图/全局架构图)→ 走 [`diagram-draw.md`](./diagram-draw.md)(独立流程,不占编号,随时可触发,不需要先过本页其它判据)。
6. **核心流程中出现 `kind:rule` 且 `tier:none` 的行**(业务已识别但页尚未建,超出"刚识别出来"的短暂窗口)→ 优先走 [`init/README.md`](./init/README.md) 骨架档三步补齐——这是 `GOVERNANCE_RULES` 的 `overview-rules.md` 四·4.5 全量规则页与 `tier:none` 短暂性不变量的修复动作,**不排队**,发现即处理,不等下一轮常规改动带出来。

## 流程中途"发现分诊结果不对"时怎么办

任一流程执行到中途,发现"这批改动其实不该按当前这条流程处理"(如 update 判定改动规模已到"整页重来"量级、或 init 发现页面其实已存在),**只能做两件事之一,不许自己决定转去另一条流程**:

- 继续按本流程完成(改动确实在本流程能力范围内);
- **停止,按下方"停止交回格式"整理判定依据,交回本页重新分诊**——是否转去别的流程、转去哪条、什么时候转,由本页(或操作本页的人/上一级编排者)重新判断,不由触发停止的那条流程自己指定或直接联系另一条流程的执行者。

## 停止交回格式

- 触发停止的判据与依据(如"update 分流判据线2 命中,受影响节点 N / 总节点 M");
- 已确认的客观事实(如是否存在代码 diff、受影响节点清单);
- 建议的下一步去向(仅作**建议**供分诊参考,不是决定)。

## 已知的分诊边界情形

- **update 分流判据(局部改 vs 整页重来)**:定义见 `GOVERNANCE_FLOW_UPDATE` 的 `step6-assemble.md`"分流判据"节;三线任一命中 → 本流程停止、交回本页重新分诊,不直接写"转 init"。该判据还有一条"零 diff 例外"(见该节),代码零 diff、纯治理重组的场景下线2 即便命中也不停,本流程原地处理。
- **init 发现页已存在**:`GOVERNANCE_FLOW_INIT` 的 `step6-assemble.md` 组装步开头先查页是否已存在,存在 → 本流程停止、交回本页重新分诊(通常会分诊到 update,但不由 init 自行断言)。
