# 规则页组装 · 初始化流程总则

> 规则与判据见 `GOVERNANCE_RULES` 的 `assembly-rules.md`;散文部分的可读性写法(编号不当叙述主语,统一放关键词后括号内)见 `GOVERNANCE_RULES` 的 `business-rule.md` 六。
> 入口分诊见 `../README.md`,本流程不重复其判据,只引用。

目标:每步范围、产出、注意事项写死,先手工跑几次固定下来,再做成独立 skill。

## 拆分标准

产物能独立检验的才单列一步。步 1 概览单独做,它的产出是步 2、步 3 的共同参照;**每步派独立执行者,上下文不混**。

初始化(一个业务做一次)按 `tier`(骨架 / 细节,定义见 `GOVERNANCE_RULES` 的 `business-rule.md` 三)分两条步骤线,编号沿用原六步序号不重排(原步 5 已整体移出本流程,见下方说明):

| tier | 走哪几步 |
|---|---|
| 骨架档 | 步 1 → 步 3 → 步 6(三步;跳过步 2 提取、步 4 校验) |
| 细节档 | 步 1 → 步 2 → 步 3 → 步 4 → 步 6(五步,原有全套) |

- **步 1** · [`step1-overview.md`](./step1-overview.md) · 概览(判断,单独做,人审后才进下一步;骨架档/细节档都走)
- **步 2** · [`step2-extract.md`](./step2-extract.md) · 提取(机械,参照步 1;**仅细节档执行**)
- **步 3** · [`step3-classify.md`](./step3-classify.md) · 归纳(判断,参照步 1 + 步 2;骨架档/细节档都走,产出按 tier 分叉)
- **步 4** · [`step4-verify.md`](./step4-verify.md) · 校验(机械,换人做;**仅细节档执行**)
- **步 6** · [`step6-assemble.md`](./step6-assemble.md) · 组装(机械,骨架档/细节档都走,组装自查按 tier 分叉)

> **跳号说明**:原步 5(出图)已整体移出本流程,独立成 [`../diagram-draw.md`](../diagram-draw.md)(不占编号,随时可触发,覆盖业务流程图/全局业务图/业务全貌图/全局架构图四类图)。本流程(概览/提取/归纳/校验/组装)全程不出现任何图的判断逻辑;组装步(步 6)图槽位一律机械占位(标准真链接,文件不存在则用 skill 提供的占位资产补位),不判断"要不要画"。步骤编号维持原有 1/2/3/4/6,不把 6 改成 5。

每步三项:**范围 / 产出 / 注意**。执行到一步结束即停,报"确定项"与"不确定项";确定项直接合并,不确定项等人定。

## 批次产物路径

初始化批次目录 `DATA_BUSINESS_RAW` 下 `init-<业务id>/`,步 1 到步 4 的产物都落这里,文件名与步骤对齐:`step1-overview.md` / `step2-exits.md` / `step3-raw.md` / `step4-verify.md`。图(SVG)不落批次目录,直接存 `DATA_IMAGES`,产出机制见独立流程 [`../diagram-draw.md`](../diagram-draw.md)(不随本批次走,可在组装前或组装后任意时点触发)。批次目录随步 6 组装那一次 `git commit` 一并入库,`DATA_LOG` 行里的 `raw:` 字段指的就是它。

## 做成 skill 前要积累的

每次手工执行记下:哪一步出了不确定项、最后怎么定的。跑 2–3 次后把反复出现的判定写进对应步的"注意",再定 skill 的边界。
