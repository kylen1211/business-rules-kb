# sum-svg-diagram · 浅色结构化 SVG 画图

从骨架母版复制、只换内容——布局、配色、构图是母版定死的,画图的人只负责把正确的内容放进正确的格子。这样保证任何人、任何会话画出来的图都长一个样。

## 选母版

| 要画的图 | 母版文件 | 版式特征 |
|---|---|---|
| 系统架构 / 组件拓扑 / 模块分层 | `assets/architecture-master.svg` | 横向分层带(竖排层名),层内结构化组件卡片,组件间语义连线,底部分层摘要面板 |
| 业务流程 / 处理链路 / 判定流 | `assets/flow-master.svg` | 多条泳道横带纵向堆叠(圆角虚线彩色容器+左上角标签芯片),泳道内步骤卡片自左向右横排,判定语义写进卡片 bullets 与连线药丸标签(不用菱形),拒绝出口为玫红卡片放在所属泳道右端,主链路蓝实线/校验链橙实线/拒绝路径红虚线,跨泳道衔接用带药丸标签的折线 |

先完整读一遍选中的母版源码再动手——母版即规范,所有布局决策(坐标节奏、间距、遮罩层序)都在里面,文字规则不再复述。

## 作业流程(六步,顺序执行)

1. **复制骨架**:把选中的母版复制为目标文件,保留头部版本注释并追加一行本图信息(图名/日期/内容事实源)。
2. **画前内容清单**(核对基线,不可省):从事实源(代码/业务页/用户口述)列出全部候选节点/组件全集,每项附一句职责摘要 + 出处;逐项按下方"结构语法"F1-F6(流程图)/A1-A2(架构图)分类判断——重点核两条:F5"是否只被别的节点内部调用取值"(命中则不单独成卡)、F6"触发入口是否全局异常通道、无固定顺序位置"(命中则不连主线);分类结果决定该节点最终是否单独成卡、是否接主链路连线。同时列出链路内顺序依据(步骤先后凭什么定序)与跨链路/跨层因果依据(哪条连线凭什么画)各自的原文出处。此清单是第5步"画后内容核对"的比对基准,不能省略或事后补写。
3. **只换内容**:把全部占位文字替换为真实内容。内容必须来自调用方给的事实源(代码、文档、用户口述),不自造、不臆测;业务语义(层名、组件名、步骤名、连线标签)一律由调用方输入决定,本 skill 不预设任何业务词表。替换完后全文检索"占位""示例""名称A/B""子能力"等占位残留,必须清零。
4. **数量伸缩**(见下方"铁律与可调基准"):按真实内容增删泳道/卡片/小格/连线,坐标按母版既有节奏线性推算(卡片高度、间距、层带高度都是等差的,新增一行=平移一个步距);画布 viewBox 随之调整,保底 30px 外边距。
5. **渲染自查 + 画后内容核对**(感知交付门,不可跳过):
   - 渲染自查:在浏览器里打开渲染后的 SVG 截图检查——文字无溢出、无元素重叠、无悬空箭头(每条连线两端都落在实体上)、无大片空白区、图例与正文一致、占位词已清零。发现问题修完再查一遍。**同批必须过一遍“SVG XML 安全”检查(见下方铁律小节)——渲染看着正常不代表 XML 语法合法,截图检查不能替代这一步,两者缺一都不算完成第5步。**
     - 可选补充闸门:画完后再跑一遍 `python3 scripts/geo_check.py <你的svg路径>`(纯标准库,无需装任何依赖)——机械核验连线是否穿卡片、连线端点是否落在泳道/层标签芯片上、药丸标签是否与卡片/彼此重叠这三类几何问题;这类问题有时恰好落在卡片空白区,肉眼截图容易漏看,脚本能补上这个盲区。退出码非 0 时按输出逐条修完再跑一遍。这一步不能替代人工目测(脚本不判断内容对不对、颜色对不对、文字是否溢出),只是补充,不能跳过人工这一遍。
   - 画后内容核对:拿第2步"画前内容清单"逐项唱名——该节点落在哪张卡片上(或按 F5 判定只在他卡 bullets 里被提及);默认判据是"编号必须出现在自己名下的卡片上,只在别处被提及不算数",F5 命中的节点是唯一例外(允许只在调用方卡片 bullets 里出现,不单独成卡)。再反过来做孤卡反查(图上每张卡是否都能对应清单里的一项,防止画出清单外的节点)、连线逐条对照顺序依据/因果依据(每条线是否都能在第2步记录的出处里找到根据)。**复杂全局图(全局业务图/业务全貌图/全局架构图)建议换人做这一步核对;单条链路的局部图可以自查。**
6. **交付**:交付 SVG 文件本体;若目标位置有约定(如项目知识库的 images/ 目录),按调用方约定落位。若本轮判"应画"但推迟实际绘制(如批量建页时先占位、后补图),复制 `assets/placeholder-pending.svg` 到目标正式文件名占位,不新起占位画法;后补真图时用真图整份覆盖该文件,不改文件名与消费方页面里的链接路径。

## 结构语法

母版的六步流程与铁律只精确覆盖母版本身示范的拓扑(流程图=线性推进+二元拒绝,架构图=分层递进+相邻层调用)。真实业务出现分支、汇聚、回环、超长链路、跨层/同层连接时,以下规则在不新增视觉元素、不突破上方铁律的前提下,规定怎么组织卡片内容、怎么走线;每条规则是对现有六要素铁律(卡片构造/连线语义/药丸标签/图例)的复用与组合,不是新铁律。

### 流程图结构语法

**F1 条件分支**
- 判据:判定卡片的后续走向 ≥2 条独立路径,且不是"一条继续推进、一条拒绝终止"这种经典二元(该情形沿用既有拒绝出口画法,不适用此规则)。均为非拒绝推进路径时,即使只有 2 条(如"无条件路径 + 条件成立才追加的路径"这种搭配),同样按本规则处理,不要求条数必须 >2。
- 画法:判定语义仍写在触发卡片的 bullets 里,不画菱形;从该卡片引出 N 条独立实线(蓝色主链路语义),各自带一个药丸标注分支条件。若某条分支目标在同一泳道内后续位置,该步骤位可由 1 张卡片变 N 张并排卡片;若导向不同泳道,逐条复用"跨泳道衔接用带药丸标签的折线"画法。分岔前不得先合并成一条线再分叉——每条分支必须从源头卡片边缘各自独立引出。若某条分支本身是终态拒绝,该条单独判为玫红虚线,不影响其余分支仍为蓝实线。

**F2 多链汇聚**
- 判据:≥2 条上游链路(不同泳道或同泳道并行卡片)最终指向同一个下游卡片。
- 画法:目标卡片 bullets 用"入口①②③"格式列出各来源(复用母版"拒绝出口(共享)"卡片的既有写法);目标卡片外观维持正常样式,不因是汇聚点而变色(除非它本身是终态拒绝,才玫红)。各来源线各自保留独立药丸标签,不强行合并成一条标签。走线拥挤问题按下方"通用走线附则"处理。

**F3 重回环 / 非失败回流边**
- 判据:需要一条跨泳道或非相邻步骤的反向连线,且语义不是简单的顺主链路推进,覆盖两类场景:①失败/超时后跳回更早步骤重新执行整段链路(重试类回环);②非失败的成功结果触发反向续接/回流(如某分支产出物触发另一分支重新生成或续接,不是失败重试)。同卡片内"最多重试 N 次"这类轻回环仍维持现状,继续用文字表达,不画连线。
- 画法:回程连线复用**橙色实线**(不新增连线颜色或线型),搭配专用药丸标签说明具体语义(①类写"校验不通过·退回步骤 X 重试"这类重试措辞,②类必须显式带"非失败重试"或等价字样,避免与①类混淆;图例条目同样按场景措辞,不能笼统写"回环");回程连线必须走一条独立的"回程走廊",不与主链路正向线共享路径,避免视觉误读为顺序前进;①类的回环触发上限等业务语义(如"超过 3 次转人工")写在源卡片 bullets 里,连线本身只画一次回环路径,不代表真实触发次数。

**F4 长链折行**
- 判据:单泳道内步骤卡片数超出版式舒适上限——按母版实际卡片宽度+间距现算:卡片宽度 × 张数 + 间距 × (张数-1) 超出基准画布宽度(扣除两侧留白与泳道内边距后的可用宽度)即触发,不设死数字。
- 画法(按优先级二选一):
  1. 优先拆泳道:若步骤能在语义上拆出独立阶段边界,直接拆成两条独立泳道(复用母版本就支持的"泳道数随内容线性伸缩"能力)。判断"是否存在语义边界"的强信号:步骤是否分属不同的业务链路/不同的规则页/不同的触发时机——命中其一即视为存在语义边界,优先拆泳道;不要因为它们共享同一个宽泛阶段名(如笼统的"装配期")就归并进同一条泳道再用换行处理。
  2. 上述强信号均不命中、拆不出语义边界、纯粹是同一条链路内步骤多——才用泳道内换行:同一条链在泳道内部纵向拆成 2 排卡片(左→右排完第一排,折下到第二排继续左→右),排与排之间用同色系连线+转折箭头衔接(复用"跨泳道衔接用带药丸标签的折线"画法,只是发生在同泳道内部);泳道高度、画布高度按新增排数线性调整。

**F5 私有零件不成卡**
- 判据:事实源里的某个节点没有自己的独立触发时机,只被另一个节点的内部逻辑调用取值/计算(事实源措辞常见"供 X 各分支调用""X 判定过程中按需计算"这类从属表述),即它是调用方的私有零件,不是流程中的一个步骤。注意区分:被多个节点共享调用、或有独立触发入口的节点不适用本条,仍正常成卡。
- 画法:不单独成卡,并入调用方卡片——在调用方卡片 bullets 里带节点编号提及其职责(如"重新记录提问基准(D06)"),保证节点不在图上丢失、可与事实源对号。若强行单独成卡,读图者会把"内部调用"误读成"流程顺序上的下一步"。

**F6 异常旁路不连主线**
- 判据:某节点属于本泳道业务,但其触发入口是全局/框架级的异常通道(错误帧路由、全局异常处理这类),没有固定的顺序位置——不是主链路上任何一步的"下一步",任何时刻满足条件都可能触发。
- 画法:卡片保留在所属泳道内(它归这个业务管),但不与主链路顺序连线相接,卡片 bullets 首行写明触发来源(如"触发:全局管线错误路由,慢脑执行失败时")。若连上主线,等于在图里捏造一个不存在的顺序因果。本条与 F3 的区别:F3 是主链路语义上真实存在的回环/回流边,要画线;本条是无顺序位置的旁路入口,不画线。

### 架构图结构语法

**A1 跨层跳跃连接**
- 判据:组件调用目标跨越 ≥2 层(如接入层直连外部服务层,跳过核心层)。
- 画法:连线仍按现有"实线同步/虚线异步"语义,走一条独立的"跳跃走廊",不与中间层的组件卡片重叠或穿越(复用"连线不穿卡片"铁律);不加专属视觉标记(不加粗、不加图标提示"这是跳跃"),靠走线路径本身的跨度自然传达跨层。

**A2 同层组件间关系**
- 判据:同一层内两个组件之间存在需要画出实际连线的直接调用/依赖关系(卡片小格文字提及即可表达清楚的场景不适用此规则,优先用文字退化表达)。
- 画法:新增该层内部的"层内走线带"(沿组件卡片顶部或底部留一条水平走廊),线型/颜色沿用现有语义(同步实线/异步虚线),不新增颜色;不与跨层连线共用走廊,避免同层线和跨层线在视觉上叠混。

### 通用走线附则(F2/A4 共用)

多个来源/组件汇入同一目标节点导致走线拥挤时(流程图多链汇聚、架构图多组件依赖同一下游节点等场景通用):
- 过道/走廊宽度按 60px 量级基准可放宽,不受基准值限制;
- 放宽后仍必须满足两条更基础的铁律:①连线不穿越任何卡片实体矩形;②无标签重叠、无悬空标签;
- 放宽后并行走线之间的横向间距允许压缩,但不得低于 20px 下限(20-25px 区间视为可接受工程容差,不因单项数值未达 25px 判不通过);低于 20px 或出现穿卡/标签重叠任一项,才判不通过。

**芯片避让**(适用范围不限于汇聚场景——任何跨泳道/跨层连线的入口出口点、以及沿途药丸标签,都要遵守):泳道/层左上角的标签芯片(标注泳道名或层名的圆角小矩形)虽不是内容卡片,但同样是不可被连线穿过、不可被药丸遮挡的实体。选定跨泳道/跨层连线的落点前,先看目标泳道/层的芯片占用区(通常在左上角,宽度随标签文字变化);连线端点、药丸矩形都不得落在该区域内,必要时把落点向右或向下平移。真实内容测试中出现过这类冲突(因 F4 拆泳道新增的跨泳道连线,进入新泳道时入口 x 恰好撞在目标泳道的标签芯片上),当时靠手工挑选安全落点绕开,现固化为规则,避免同类冲突下次仍要临场判断。

## 铁律与可调基准

**铁律(不可改,改了就不是这套风格了)**:
- 配色系统与语义分工:架构图按分层类型着色(青=接入/校验、绿=核心/执行、紫=数据/研发态、橙=外部/判定框、玫红=拒绝/失败、蓝=起止);流程图泳道容器按顺序各配一个强调色(母版示例蓝/紫/绿依次),拒绝出口统一玫红;
- 字体栈与字阶(标题/卡片标题/要点/药丸/角标各级字号与字重照母版);
- 卡片构造(标签芯片+粗标题+子能力小格/要点行);流程图判定语义写进卡片 bullets 与连线药丸标签,不画菱形;层带/泳道容器的画法;
- 连线语义:架构图实线=同步/实时、虚线=异步/后台、双端箭头=双向;流程图主链路=蓝实线、校验链=橙实线;两套母版共用失败/拒绝路径=玫红虚线;每张图底部必有图例,且只列图中实际用到的语义;
- 拒绝/终止类出口放在所属泳道/区域的右侧,不与正常流转节点混排;
- 绘制层序:背景 → 容器 → 连线 → 卡片(先遮罩后着色)→ 文字 → 药丸 → 图例。

**可调基准(随内容线性伸缩)**:
- 泳道数、层数、卡片数、小格数、判定数、连线数;
- 画布宽高、层带高度、卡片宽度(按内容文字长度调,CJK 字符宽度约为字号等宽,估算后留余量);
- 摘要面板要点条数、依赖注释框的有无。

## 内容质量要求

- 每张图注明内容事实源与核对日期(标题副行),内容逐条可回溯;
- 图上文字与事实源冲突时以事实源为准,发现事实源本身可疑要向调用方报告而不是照抄;
- 文字风格:卡片要点用"加粗关键词 + 浅色说明"结构,短语不成段;连线药丸是业务语义短语,不是箭头方向的复述。

## SVG XML 安全(铁律,不可跳过)

产出的 SVG 本质是一份 XML 文件,内容正确不代表语法合法——以下两条对任何母版(架构图/流程图)、任何消费方一律适用,与作业流程第5步"渲染自查"同批执行,不能因为截图看着正常就跳过:

- **注释安全**:严禁在 XML 注释(`<!-- ... -->`)里写任何包含三连短横(`---`)或箭头符号(`->`、`<-`、`-->` 等)的内容——这类字符序列在注释里可能被解析为提前终止符或产生歧义,轻则破坏渲染、重则截断后续内容。需要表达"步骤 A 推进到步骤 B"这类语义时,注释里用中文箭头符号(`→`)或文字描述,不用 ASCII 箭头组合。
- **文本转义**:正文文本内容中的 `&` 一律转义为 `&amp;`,`<` 转义为 `&lt;`,`>` 转义为 `&gt;`;不要假设内容里不会出现这些字符——画完后按这三个字符各自全文检索一遍确认(尤其是从代码/文档摘取的原文片段,常见 `&&`、`<=`、`>` 这类符号未转义直接粘进卡片文字的情况)。

这两条不属于版式/配色/构图范畴,不随母版版本号变化;违反任一条不是"风格不对",是产出物本身不合法,必须在交付前修完。

## 版本

母版头部注释带版本号;母版任何改动(配色、几何、构图)都要在 `CHANGELOG.md` 记一条并递增版本号。消费方(各项目知识库)看到版本变化时自行评估是否重画存量图,不强制回溯。
