# 步 -1 · 项目事实登记

判断轻、以盘点为主。只在 `DATA_PROJECT_FACTS` 不存在或缺字段时执行。内容取自 `GOVERNANCE_FLOW_SETUP`（项目适配），产出与它一致，完成后等同于走过一次项目适配。

## 范围

盘点下列事实，**只记录客观事实，不做分类判断**，写进 `DATA_PROJECT_FACTS`（新建；已存在则只补缺的字段，已有字段不改）：

- **项目名**：取仓库目录名或承载文档自称的项目名，与 `GOVERNANCE_RULES` 的 `overview-rules.md` 一节的项目名取法一致。
- **主语言 / 运行时**：如实记录（可以是多个，如「TypeScript/Node ESM + 若干 Python 脚本」），不强行归一成一种。
- **标准排除句用词清单**：业务代码调用、但内部实现不需要本体系索引的第三方框架/运行时/SDK 具体名称（如某项目的 Node 运行时、MCP SDK；另一项目的 Python asyncio、pipecat）——供步 1 页头的标准排除句直接取用。
- **代码位置**：编排者派发时已和用户确认，原样写入（相对挂载所在仓库根的路径，同仓写 `.`；多个仓库逐行 `<名称>: <路径>`）。
- **代码索引排除路径**：会让同一份代码被索引两次的路径（符号链接、生成副本等），在每个代码根下查：`find . \( -name .git -o -name node_modules -o -name .venv \) -prune -o -type l -print`，找出指向项目内代码的符号链接；没有就写「无」。
- **完成日期**：当天。

## 产出

`DATA_PROJECT_FACTS`，格式：

```markdown
# 项目事实卡

- 项目名：<值>
- 主语言 / 运行时：<值>
- 标准排除句用词清单：<逗号分隔>
- 代码位置：<路径；多个则换行缩进逐行列出>
- 代码索引排除路径：<路径，或「无」>
- 完成日期：<YYYY-MM-DD>
```

## 注意

- 不判断核心流程有哪些环节、哪些是配件——那是概览初始化的事，本步只交「这个项目是什么」。
- 信息不全时（如两种主语言、排除句用词一时列不全），如实记录已确定的部分，在回执里列为不确定项，不臆造。
- 不改 `GOVERNANCE_RULES` / `GOVERNANCE_FLOW` 下任何方法论文件。

## 通过判据

`DATA_PROJECT_FACTS` 存在且六项均非空；「代码位置」登记的每个路径都存在。

## 回执

- 产出文件路径，以及写入的六项原文
- 新建还是补了哪几项
- 不确定项：每条写清是什么、为什么定不了、倾向哪边
